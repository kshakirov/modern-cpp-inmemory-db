# Modern C++ In-Memory Relational Algebra Query Engine

## 🎯 Манифест и Философия проекта

Этот проект — не просто написание очередной СУБД "в лоб". Это инженерно-исследовательская лаборатория, цель которой — спроектировать строго типизированный, компилируемый движок реляционной алгебры в памяти, опираясь на фундаментальные компьютерные науки, идеи обобщенного программирования Александра Степанова и системный прагматизм Бьёрна Страуструпа.

### 🏛️ Ключевые принципы разработки:
1. **Отказ от ООП-оверхеда**: Никакого динамического полиморфизма (виртуальных функций), скрытых указателей и стирания типов в рантайме. Данные и алгоритмы ортогональны. Применяются чистые функции и Compile-Time метапрограммирование.
2. **Симбиоз с Железом («Танго и Кэш»)**: Данные организуются по принципу SoA (Structure of Arrays / Колоночное хранение). Физическая структура обязана быть кэш-локальной, плотной и непрерывной в памяти, обеспечивая максимальную утилизацию L1/L2 кэша и аппаратную SIMD-векторизацию.
3. **Строгость Теории Типов**: Проект опирается на концепции Боба Харпера (акцент на статической верификации и произведениях типов). Все схемы таблиц и реляционные контракты проверяются компилятором (GCC 15) на этапе сборки. Ошибки в именах колонок или несовместимость типов вызывают ошибку компиляции, а не рантайм-панику.
4. **Ленивые вычисления и Потоковость**: Движок проектируется с учетом работы с тяжелыми асинхронными потоками данных без полной материализации их в памяти. Логические операторы реализуются как ленивые конвейеры (на базе C++20 Coroutines).
5. **Формальная верификация**: Архитектура изначально затачивается под Property-Based Testing (проверка алгебраических законов реляционной алгебры на случайно сгенерированных данных) и Bounded Model Checking.

## 🏗️ Архитектура системы (Высокий полет)

### Реализация Слоя Хранения (Текущий статус)
* **Реляция (Таблица)** — представляется как фиксированный гетерогенный вектор времени компиляции: `std::tuple` из `std::vector<T>`.
* **Compile-Time Метаданные** — строки-имена колонок передаются как параметры шаблонов (C++20 Non-Type Template Parameters / NTTP). Доступ к колонкам по строковому имени преобразуется компилятором в прямое смещение по индексу кортежа с нулевой стоимостью в рантайме (Zero-Cost Abstractions).

## 🧪 Компаративный анализ (План исследований)
В процессе реализации проводится регулярный параллельный анализ того, как аналогичные математические абстракции выражаются в других парадигмах:
* **Haskell (HINQ)**: Сравнение ленивости C++ корутин с ленивостью Haskell, оценка overhead сборщика мусора и thunks.
* **Rust**: Анализ zero-cost абстракций на трейтах и проверка того, как аффинные типы (система владения Memory Ownership) могут гарантировать безопасность параллельного доступа к таблицам на уровне компиляции.
* **Go**: Анализ каналов как примитивов стриминга и подсвечивание узких мест из-за отсутствия дженерик-специализации для примитивов в старых подходах.

## 🤖 Протокол взаимодействия
* Код не пишется автоматически, пока об этом не будет заявлено эксплицитно.
* Основной упор идет на навигацию, критику архитектуры, сократовские вопросы и разбор особенностей железа.
* Знания добываются пошагово, через глубокое понимание каждого архитектурного компромисса.
